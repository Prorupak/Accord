# Getting help

- **Questions and ideas:** GitHub Discussions, once they are enabled on the repository. Until
  then, open an issue and say it is a question.
- **Bugs:** open an issue with the bug report form. Include steps to reproduce and a small
  synthetic CSV if the problem depends on the data.
- **Feature requests:** open an issue with the feature request form. Describe the problem before
  the solution.
- **Security vulnerabilities:** report them privately, as described in [SECURITY.md](SECURITY.md).
  Never in a public issue.

Before asking, check `README.md`, `CONTRIBUTING.md`, `docs/docker.md` and `api/README.md`.
Support is best effort from a single maintainer.
